Cloud calling keeps registration in the provider cloud and reaches the PSTN through a carrier plan, an operator connection, or a customer SBC. Cisco documents Local Gateway (often CUBE) for Webex Calling. Microsoft documents three Teams Phone PSTN models: Calling Plans, Direct Routing, and Operator Connect. Zoom Phone, RingCentral, 8x8, Dialpad, and Google Voice are other cloud voice services. Webex App media is UDP 8500–8699 (audio 8500–8599, video 8600–8699). Webex Calling cloud media destinations are UDP 5004, 9000, 8500–8699, and 19560–65535. Certificate-based Local Gateway SIP is TCP 5062; registration-based is TCP 8934. Teams client media is UDP 3478–3481 toward 52.112.0.0/14, 52.122.0.0/15, and 2603:1063::/38. Direct Routing SIP is TCP 5061 to sip.pstnhub.microsoft.com, sip2.pstnhub.microsoft.com, and sip3.pstnhub.microsoft.com. Zoom, RingCentral, 8x8, Dialpad, and Google Voice media ranges are still not stated.

      Failure tree

      Direct Routing trunk stays down

      Checks. TLS certificate, FQDN, and SIP OPTIONS toward Microsoft. Do not invent the FQDN.

      Likely cause. The name on the certificate does not match the trunk, or TCP 5061 to sip.pstnhub.microsoft.com (or sip2, or sip3) is blocked.

      Fix. Match the name Microsoft provisioned. Allow UDP/SRTP 3478–3481 and 49152–53247, and the ranges 52.112.0.0/14 and 52.120.0.0/14.

      Inbound calls fail, outbound works

      Checks. Which numbers are assigned to the trunk or Local Gateway.

      Likely cause. The cloud still points the DID at the old route.

      Fix. Move the number in the provider admin, then test one DID.

      Local Gateway registers and calls return 404

      Checks. Dial-peer or route on the gateway, and the called-number format the cloud sends.

      Likely cause. The cloud sends E.164 and the gateway expects a different digit string.

      Fix. Normalize on the gateway. Keep a sample INVITE.
