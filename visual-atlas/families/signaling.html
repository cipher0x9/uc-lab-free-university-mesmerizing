SIP (RFC 3261) is the default session protocol: methods, responses, dialogs, and SDP offer/answer (RFC 3264). H.323 uses H.225.0 for RAS and Q.931-based call signaling, and H.245 for media control. MGCP (RFC 3435) lets a call agent drive a gateway. Cisco SCCP is proprietary. H.248/Megaco is the ITU gateway-control protocol. WebRTC media is set up with ICE, STUN, TURN, and DTLS-SRTP; SIP can ride WebSocket (RFC 7118).

              Failure tree

              INVITE retransmits, no 100

              Checks. Does the next hop answer UDP 5060 or TCP 5060? Is the Via address one the next hop can reach?

              Likely cause. The request is not arriving, or the response is routed to the wrong address.

              Fix. Check the listening port and that rport (RFC 3581) or a correct Via is in use on UDP.

              200 OK, then the call drops

              Checks. Was ACK sent, and did it follow the Contact / Route set?

              Likely cause. ACK never reached the UAS, so the UAS retransmits the 200 and then gives up.

              Fix. Capture both legs. ACK for a 2xx is end-to-end and is a new transaction.

              Transfer completes one way only

              Checks. REFER response, then the NOTIFY sipfrag, then the new INVITE.

              Likely cause. The transferee sent 202 but the referred INVITE failed, or NOTIFY was blocked.

              Fix. Read the sipfrag status in NOTIFY before clearing the original dialog.
